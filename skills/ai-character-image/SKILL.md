# AI 拟人角色生图

把用户指定的 AI 转化为有辨识度、可持续创作的拟人角色，并实际调用生图工具交付图片。支持不同角色，不预设统一性别、服装或世界观。用户只要设定或提示词时，仅交付所请求的内容。

## 理解角色与本次任务

- 用户提到以下名称或别名时，读取对应角色文档；所有英文部分均不区分大小写，包括中英文混合称呼中的英文部分。仅加载本次涉及的角色文档，多角色同框时分别读取对应文档。
  - DeepSeek：`deepseek`、大鲸鱼、鲸鱼、小鲸鱼、鲸鱼娘、大肥鱼、大鲸鲸、小鲸鲸 → [DeepSeek 角色约定](references/deepseek.md)。
  - Claude：`claude`、`Claude娘`、克劳德、克劳德大小姐 → [Claude 角色约定](references/claude.md)。
  - ChatGPT：龙娘、`ChatGPT`、`GPT`、`ChatGPT娘`、`GPT娘` → [ChatGPT 角色约定](references/chatgpt.md)。
  - Gemini：`Gemini`、美国豆包、哈吉米、哈基米、`gemini娘` → [Gemini 角色约定](references/gemini.md)。
  - Grok：`Grok`、`Grok娘` → [Grok 角色约定](references/grok.md)。

### 无法识别称呼时的处理

1. 先结合当前对话和上述别名判断用户指的是哪个 AI；已有明确对应关系时直接使用，不重复搜索或提问。
2. 如果仍无法判断，使用可用的联网搜索工具，搜索用户的称呼及与 AI 相关的必要关键词，核对搜索结果的上下文与来源。不要把整段聊天或无关私人信息作为搜索内容，也不要仅凭单条含糊结果确定角色。
3. 搜索后能够明确对应时，简短说明识别结果并附依据链接，再读取对应角色文档继续。搜索无结果、结果存在歧义，或联网工具不可用、搜索失败时，进入交互式提问，不猜测角色身份。
4. 使用 `request_user_input_async` 等当前环境可用的交互式提问工具，弹出问题窗口，明确询问该称呼指哪个 AI，并提供可点击的候选选项。优先列出搜索与上下文支持的候选；没有有效候选时可列出 DeepSeek、Claude、ChatGPT、Gemini、Grok。窗口必须允许用户自行补充输入，不能将选择范围限制为这些角色，也不能只在普通聊天中列出问题或编号选项。使用工具原生的自由输入能力，不自行添加重复的“其他”占位选项。
5. 等待用户选择或补充后再执行依赖角色身份的生图操作；预选项和等待超时都不代表用户已作答。若当前环境没有可用的交互式提问工具，如实说明该能力不可用并暂停依赖角色身份的步骤，不以聊天问题冒充交互式窗口。

## 可覆盖的默认值

| 项目 | 默认处理 |
| --- | --- |
| 数量 | 1 张；多张按用户要求生成，不附加候选套餐 |
| 画风 | 清晰的二次元角色插画；已有角色延续其认可画风 |
| 性别与年龄感 | 沿用已有设定；首次设计采用成年、中性形象；用户说“AI 娘”等时遵循其表达 |
| 构图 | 单角色全身立绘，竖向构图，头部和脚部完整入画；头像等用途优先 |
| 场景 | 简洁浅色背景，突出角色；具体场景按用户要求 |
| 画面文字 | 无文字；用户要求文字时逐字保留，不擅自加名称、标语或水印 |
| 透明背景 | 默认不透明；要求透明时使用工具的真实透明背景能力 |
| 输出规格 | 使用工具支持的原生规格；不承诺工具无法保证的精确像素 |

## 维持可辨识的形象

1. **识别角色并读取文档。** 按前面的名称与别名规则确定 AI 对象，再读取对应的独立角色文档。称呼无法确定时，先完成搜索和交互式澄清，再继续生图。已识别的 AI 如果没有独立文档，采用用户提供的设定与通用默认值，不套用其他角色的设定。
2. **按角色文档查找参考图。** 以对应文档中约定的路径为准；当前各角色的参考图位于 `assets/reference-images/` 下的角色子目录。用户未指定形象参考图时，默认同时读取该角色目录中的 `Front view.webp` 和 `Three-view drawing & Design reference sheet.png`，共同作为形象参考并传入生图工具；用户明确指定参考图或参考范围时，以用户要求为准。本地图片先使用 `view_image` 逐张查看，不仅凭文件名推断外貌。任一所需图片缺失或无法读取时，如实说明具体文件，不声称已完整加载；用户要求严格延续某张缺失的参考图时，请其重新提供，否则可按现有参考图与文字设定进行创作。
3. **明确每张参考图的用途。** 分别标注角色身份、服装、画风、姿势、构图或待编辑原图。用户提供的图只用于其指定的维度；聊天截图和文字记录默认提供主题，不自动复制头像、界面、水印或全部对白。文件放入参考目录不等于其中所有细节都是已确认的固定人设。
4. **区分保持项与变化项。** 本次明确要求优先，其次是用户认可的设定和参考图，再采用角色文档约定与通用默认值。保持项包括已确定的脸型、发型、发色、瞳色、轮廓、标志配饰和主要配色；变化项包括本次要求的服装、动作、表情、画风与场景。服装仅在被明确指定为标志造型时固定，用户仍可要求重设计。参考资料对关键外貌存在冲突且无法从上下文确定时，通过交互式选项澄清。
5. **逐个角色整理。** 多角色同框时分别读取各自文档和参考图，明确各自外形、位置、动作与互动关系，避免串用配色和配饰。延续角色优先使用用户认可的图片，不承诺仅凭相同角色名称就能保证形象一致。

只整理本次生成需要的设定，不强制创建额外角色档案，也不将暂定创意写成已确认设定。

## 组织提示词并执行生图

### 组织本次提示词

先判断任务是首次设计、延续角色生成新画面，还是编辑现有图片；编辑任务必须明确待编辑原图。以已读取的角色文档、实际查看的参考图及用户要求组织提示词，不只发送一个 AI 名称。

每张图片按需包含以下内容：

| 内容 | 写入提示词的信息 |
| --- | --- |
| 任务与用途 | 新图或改图，以及头像、立绘、设定图或场景插画等用途 |
| 角色与参考 | AI 对象、具体外貌特征、每张输入图的对应角色和用途 |
| 保持与改变 | 必须保留的特征、本次允许修改的部分；改图时明确只改变哪些内容 |
| 画面内容 | 表情、动作、服装、道具、场景；多角色的站位及互动关系 |
| 视觉呈现 | 画风、构图、配色和光线；未指定的项目沿用前面的默认设置 |
| 精确要求 | 用户要求的原样文字、透明背景、宽高比或尺寸，以及需要避免的内容 |

保留用户已经给出的细节，只补足完成画面所需的信息。用户要求直接生成时，简短说明采用的角色、参考和本次变化后执行，不增加提示词审批步骤；用户要求先看方案、先确认提示词或只写提示词时，停在相应阶段。

### 调用生图工具

- 默认使用内置 `image_gen`，按照当前工具的实际参数和图片引用方式调用。将参考图实际传入工具，不能只在提示词中写本地路径；所有必要图片都应可引用，缺失时不能悄悄省略。
- 只将工具支持的参数作为调用参数。用户要求的比例或尺寸如无法保证，应说明限制，不把提示词要求称为已实现的输出规格。
- 透明背景请求使用工具的真实透明能力；改图保留原有透明度，除非用户要求改变。棋盘格图案不能冒充透明背景。
- 默认数量与其他视觉设置保持前面的默认值。多张图片按顺序生成，每张都包含完整的角色特征与各自场景，不额外生成候选套餐；用户未要求时不派生并行代理。
- 工具不可用或调用失败时如实说明，不把提示词当作图片交付，不自动切换需要密钥或额外费用的服务。用户明确选择 API 或其他服务后再采用对应流程；环境提供 `imagegen` 技能时读取其相关说明。

### 检查结果与修正

生成后查看结果，与本次要求及参考图对照：角色识别特征是否保留，多角色特征是否混用，动作、手部和道具接触是否合理，文字、构图与背景是否符合要求。工具未提供可查看结果时，不声称已完成视觉检查；未核实文件透明度或尺寸时，也不声称已验证这些属性。

明确偏离要求时，保持原有角色约束，针对问题修正一次。默认每张最多两次调用，包含首次生成；仍不满足时说明实际偏差，交付已有可用结果，不无限重试。工具明确拒绝的请求不通过换服务规避。

## 交付与后续修改

1. **展示结果。** 优先展示最终图片，简短说明对应角色与本次变化。多张图片逐张标明角色或场景，方便用户指定后续修改对象。存在未解决的偏差时明确指出；没有成功生成图片时如实说明，不以文字方案冒充完成。
2. **按用途保存。** 预览可以直接使用工具原生展示。项目素材或用户要求保存的图片，将工具实际返回的文件复制到指定目录；未指定时使用当前项目的 `output/ai-character-image/`。文件名区分角色、场景与版本，不覆盖已有文件，不将生成结果自动写入技能的参考图片目录。
3. **提供实际交付信息。** 保存后给出可点击的真实文件路径；工具未返回可保存文件时说明情况并展示已有原生结果，不猜测路径。用户需要提示词时提供最终实际使用的版本；只报告已核实的尺寸、格式或透明度。
4. **从选定版本继续修改。** 用户指出某张图后，以该图作为编辑基础，结合该角色文档和必要参考图，明确本次改变及其余保持项。多图场景下修改对象不明确时，使用交互式选项澄清；不擅自选择另一版本或重新设计整个角色。
5. **保留版本与设定边界。** 修改结果另存新版本，沿用上述检查与交付流程。单次换装、换场景或新生成图片不自动成为角色默认设定；只有用户明确要求更新长期设定或参考图时，才修改对应角色文档或参考素材，不影响其他角色。
